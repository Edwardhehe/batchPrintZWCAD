# 2026-09-02

## 创建 LA.BatchPlot 解决方案

- 用 `dotnet new sln -n LA.BatchPlot` 在仓库根目录创建 `LA.BatchPlot.sln`，并加入现有 4 个项目：
  - `BatchPlotter.csproj`（net48，ZWCAD，输出到 `bin\`）
  - `AcadBatchPlot.csproj`（net48，AutoCAD.NET 20.0.1，输出到 `bin-acad\`）
  - `AcadBatchPlot.Core.csproj`（net8.0-windows，AutoCAD.NET.Core 25.0，输出到 `bin-acad2025-2027\`）
  - `src/PianNoCN/PianNoCN.csproj`（net45;netstandard2.0，被前三者 ProjectReference）
- 注意：`dotnet sln add` 会按目录自动建虚拟解决方案文件夹，给 PianNoCN 套了一层无意义的 `src` 文件夹，已手工从 sln 中删除该 folder 节点与 NestedProjects 段，保持 4 个项目平级。

## ZWCAD API 引用改为 NuGet 包（用户指定的方案）

- `BatchPlotter.csproj` 原先用 `<Reference>` + 硬编码 HintPath 引用 `C:\Program Files\ZWSOFT\ZWCAD Enterprise\ZwManaged.dll` / `ZwDatabaseMgd.dll`，本机没装 ZWCAD 导致 735 个 CS0246。
- 已删除该 `<Reference>` 组，改为：
  ```xml
  <PackageReference Include="ZWCad.Net.2025" Version="1.0.0" ExcludeAssets="runtime" />
  ```
  `ExcludeAssets="runtime"` 使 ZwManaged.dll / ZwDatabaseMgd.dll 不复制到输出目录（运行时由 ZWCAD 宿主提供），已验证 `bin\` 下确实没有这两个 DLL。
- 连带更新文档：README「开发」章节（删掉"手工改 HintPath"的旧说明，改为 NuGet 说明 + 新增 sln 编译命令）、`docs/ARCHITECTURE.md` 附录 B 外部依赖表。
- 结果：`dotnet build LA.BatchPlot.sln -c Release --no-incremental` → 5 个输出全部生成，0 警告 0 错误。

## 项目文件迁移到 src\<项目名>\

- 三个平台 csproj 从仓库根移到 `src\<项目名>\`（与既有 `src/PianNoCN/PianNoCN.csproj` 约定一致），用 `git mv` 保留历史：
  `src/BatchPlotter/`、`src/AcadBatchPlot/`、`src/AcadBatchPlot.Core/`。
- `Directory.Build.props` 新增 `<RepoRoot>$(MSBuildThisFileDirectory)</RepoRoot>`；各项目用 `$(RepoRoot)bin\` 等绝对输出路径，
  保证输出目录仍在仓库根，打包脚本不受影响。`obj` 保持相对（各项目目录内），与 PianNoCN 一致。
- **关键坑**：4 个 WPF XAML 在 `src\Common\Views`，项目移出根目录后默认 Page 通配符抓不到。必须显式：
  ```xml
  <EnableDefaultPageItems>false</EnableDefaultPageItems>
  <Page Include="..\Common\**\*.xaml">
    <Link>Common\%(RecursiveDir)%(Filename)%(Extension)</Link>
    <Generator>MSBuild:Compile</Generator><SubType>Designer</SubType>
  </Page>
  ```
- `BatchPlotter.csproj` 顺带从"默认通配符 + 27 行 Compile Remove"改为 `EnableDefaultCompileItems=false` + 显式 Include，
  与另两个项目同构，新增 tests/tmp 等目录不会再意外进入编译。
- 同步更新：`LA.BatchPlot.sln`、`scripts/build-dll.ps1` 的 Project 路径、README「开发」章节、`docs/ARCHITECTURE.md` 12.3 表与 13 节目录树。

## 重要结论：Common 不能抽成独立共享程序集

`src/Common` 有 69 处 `#if AUTOCAD / #if ACAD_CORE / #if ZWCAD`，是平台相关的共享**源码**，
必须随各平台项目按自身编译常量分别编译并内联进单个 DLL（CAD 用 NETLOAD 加载单文件）。
抽成单独程序集会让三平台共用同一份编译产物，直接破坏插件。当前"三份内联"的设计是正确的。

## 环境 / 工具坑

- 本机未安装 ZWCAD（`C:\Program Files\ZWSOFT\` 不存在）。改用 NuGet 包后不再需要本机安装。
- `$([MSBuild]::EnsureTrailingSlash('$(X)'))` 在本机 MSBuild 上**不生效**（属性原样返回），改用条件函数 `Condition="!HasTrailingSlash('$(X'))"` 可靠。
- Git Bash 会把 `-p:Prop="C:\a\b"` 中的反斜杠 mangle 成正斜杠；测试 MSBuild 路径参数时加 `export MSYS_NO_PATHCONV=1`。
- SDK：9.0.314 / 10.0.400；global.json 锁定 9.0.100（rollForward latestMinor）。
- `dotnet build <proj> -getProperty:<Name>` 可快速验证 MSBuild 属性求值结果，调试 csproj 很好用。
- `dotnet build <proj> -getItem:<ItemType>` 输出 **JSON**（含 \uXXXX 转义），可用脚本解析 FullPath 做项目项清单比对；
  这是验证"重构后编译集合未变"的可靠手段。
- 本机 PowerShell 执行策略禁止运行 .ps1（`build-dll.ps1` 无法直接执行），改跑等价 dotnet build 命令验证。
- Windows 原生 Python 无法识别 Git Bash 的 `/tmp/x.py`，需传 Windows 路径。
- 批量删除超过 50 个文件会触发 safe-delete 确认拦截；遗留的旧 `obj/BatchPlotter` 等目录未清理。
