# 修复报告：通用型批打"空框过滤"恒真失效

- 修复日期：2026-09-13
- 修复对象：`src/Common/Services/Scanning/RectangleFrameScanner.cs`（共享源码，ZWCAD / AutoCAD 2015-2024 / AutoCAD 2025-2027 三平台同时生效）
- 问题编号：全面审查报告（`docs/代码审查报告_2026-09-13.md`）K1，严重级
- 关联文档修订：`docs/ARCHITECTURE.md` §5.3

## 一、问题描述

通用型批量打印（`ZBP_RECTANGLE_BATCH_PLOT`）扫描出的候选矩形会经过"空框过滤"（`FilterEmptyRectangles`），目的是把**框内没有任何绘图内容的空矩形**（如临时标注框、图例框）从打印清单中剔除。

但实际实现中该过滤**完全不起作用**：所有通过纸张比例筛选的候选矩形无一被过滤，恰好符合纸张比例的空矩形照样进入打印清单，打出空白页。

## 二、根因分析

过滤逻辑分两步：

1. **预扫描收集**（`CollectEntityBoxesForContentCheck`）：一次性把布局内**所有**实体（含嵌套块）的世界坐标外包盒收进 `entityBoxes` 列表；
2. **逐候选判断**（`AnyIntersects`）：候选矩形只要与**任意一个**外包盒相交，就认为"框内有内容"，予以保留。

问题出在第 1 步没有做任何排除：**候选矩形自己的边框实体**（识别出该框的那条闭合多段线，或拼出该框的 4 条直线）本身也是布局内的实体，其外包盒必然与候选矩形相交 → `AnyIntersects` 恒真 → 过滤器形同虚设。

而代码注释（"非矩形框自身的实体"）和 `ARCHITECTURE.md` §5.3（"矩形框多段线自身不计为内容"）都**声称已经排除了自身边框**——即文档描述的是正确行为，实现从未做到，三者不一致，实现是错的。

## 三、方案选型

### 3.1 采纳的判据

修复采用与人工检查完全一致的判据：

> 用候选矩形的范围去查内容，**如果命中的只有组成识别框的实体**（闭合多段线、四条独立边、或产生该框的块参照），**没有其他对象，它就是空白矩形**。

关键在于"组成识别框的对象"必须是**按候选区分**的：候选 A 只排除 A 自己的边框；相邻候选 B 的边框对 A 而言仍然是内容。

### 3.2 检测引擎的选择（为什么不用 Editor.SelectCrossingPolygon）

评审过程中曾建议用 `Editor.SelectCrossingPolygon(候选框四角点)` 做逐框选择验证——"选中对象只有组成识别框的实体即空白"。该思路的**判据**与最终实现一致，但其**检测机制**与扫描器的运行场景存在硬冲突：

| 约束 | 说明 |
| --- | --- |
| 视图依赖 | `SelectCrossingPolygon` 只能选中当前视口内可见的实体（即建议中标注的前提"需要把视图矩形显示在视图显示范围内"） |
| 多布局扫描 | `ScanScope` 支持"全部空间/图纸布局"扫描，未激活的布局根本无法执行选择；要做到可靠必须逐候选"切布局 + ZOOM + 重生成" |
| 跨文件批打 | 并排打开的 DWG 不是活动文档，视图相关选择直接失效 |
| 性能与体验 | 逐候选 ZOOM 是 O(R) 次屏幕重绘，数千候选时扫描耗时成倍增加，且扫描期间屏幕频繁跳动，与现有进度窗口、非模态面板"不抢焦点"的设计（`CadWindowFocus` 等）相悖 |

因此最终实现保留原有的**一次性预扫描 + 内存相交判断**引擎（O(E + R×B)，无视图依赖、不闪屏、支持取消），把建议中的判据落实为"按候选排除边框实体"。二者语义对齐且更保守：外包盒相交是几何穿越的**超集**——宁可少过滤（保留个别大实体包盒恰好压住的空框），绝不会误删真图框。

## 四、修复实现

全部改动集中在 `src/Common/Services/Scanning/RectangleFrameScanner.cs`（+177 / -42 行），核心思想：**在收集候选的同时登记每个候选的"边框实体 ObjectId 集合"，空框判断时按候选排除这些实体**。

### 4.1 新增的数据结构

| 结构 | 作用 |
| --- | --- |
| `SpaceRectangles` | 单空间收集结果容器：`Rectangles`（候选列表）+ `BorderEntityIds`（候选 → 边框实体集合字典）。`LocalRectangle` 未重写相等比较、按引用相等使用，可安全作为字典键贯穿整条过滤流水线（窗口裁剪、纸张匹配、去重均不复制实例） |
| `LineSegment.SourceEntityId` | 四线拼合的每条线段记录来源实体（`Line` / 直线型开放 PL / 老式 POLYLINE）的 ObjectId |
| `CachedBlockRectangle` | 块定义缓存条目：除缓存局部坐标最大矩形外，同时缓存其边框实体链。`BlockDefinitionCache` 的值类型由 `List<LocalRectangle>` 改为 `List<CachedBlockRectangle>` |
| `ContentBox` | 内容外包盒条目：外包盒 + 所属实体 ObjectId。内容收集不再只收集裸几何 |

### 4.2 边框实体的登记规则（按候选来源分路径）

1. **闭合多段线候选**（分支 1 / 1b / 1c，含 `Polyline` / `Polyline2d` / `Polyline3d`）：
   边框 = 多段线自身 ObjectId。
2. **四线拼合候选**（`FindRectanglesFromSegments`）：
   边框 = 组成矩形的 4 条线段各自的来源实体 ObjectId（去重）。
3. **块内候选**（分支 2，块定义内识别出的矩形）：
   边框 = 定义内部边框实体（嵌套多段线/四条边，以及更深层的嵌套块参照链）+ **当前块参照**的 ObjectId。块参照自身的 `GeometricExtents` 也会进入内容收集，若只排除内部多段线而漏掉块参照，过滤仍会失效，因此必须登记完整链路。
   - 缓存命中路径：从 `CachedBlockRectangle` 取出定义内部边框实体，再叠加当前参照；
   - 缓存填充路径：取"最大矩形"的登记结果存入缓存，同一定义的多个实例共享内部实体、各自叠加自己的参照。
4. **未登记的候选**（理论上不存在的兜底）：退回不排除行为——宁可不滤，不可误删。

登记函数：`RecordBorderEntities`（单实体）与 `AddBlockInstanceRectangle`（块实例，实体链 + 参照）。

### 4.3 判断阶段的排除逻辑

```csharp
private static bool AnyIntersects(
    List<ContentBox> boxes,
    LocalRectangle target,
    HashSet<ObjectId> excludedEntityIds)
{
    foreach (var box in boxes)
    {
        if (Intersects(box.Box, target) && !excludedEntityIds.Contains(box.EntityId))
        {
            return true;
        }
    }
    return false;
}
```

每个候选只排除**自己登记的**边框实体；其余任何实体（包括其他候选的边框）与候选相交仍算内容。复杂度保持 O(E + R×B) 不变——排除集合查询只发生在已相交的盒子上，预扫描也只多存一个 ObjectId。

### 4.4 各场景推演

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 空白矩形（恰好符合纸张比例） | 保留（自己的边框算"内容"） | **过滤** ✓ |
| 空白矩形 + 框内一行文字 | 保留 | 保留（文字算内容）✓ |
| 真实图框（边框 + 标题栏图素） | 保留 | 保留（框内图素算内容）✓ |
| 图框块（块内含边框 + 标题栏） | 保留 | 保留（块内其他图素算内容）✓ |
| 只有边框多段线的空图框块 | 保留 | **过滤**（多段线与块参照自身均被排除）✓ |
| 四条独立线拼出的空框 | 保留（4 条边算"内容"） | **过滤** ✓ |
| 相邻两个真图框 | 保留 | 保留（彼此的边框对对方仍算内容）✓ |
| 框套框（内框在外框内） | 外框保留、内框去重阶段处理 | 不变（内框的边框对外框仍算内容）✓ |

### 4.5 有意保留的保守边界

两种"双重描边"场景沿用修复前行为（保留候选），不做激进取舍：

1. **同一位置重复描边的空框**（用户把空矩形画了两遍）：去重只保留面积序在前的实例，被舍弃实例的边框**不并入**保留候选的排除集，仍算内容 → 候选保留；
2. **同实体多角色**（如端点相接的开放多段线既是矩形候选又是四线拼合的边）：各路径独立登记，互不影响。

### 5.2 建议的 CAD 内人工验证清单

1. 画一个恰好符合 A4 比例（或任一内置纸张比例）的空闭合多段线 → 通用型扫描 → **不应出现**；
2. 同一矩形内加一行文字 → 扫描 → 应出现；
3. 真实图框（含标题栏图素）→ 扫描 → 应出现，图号/图名识别正常；
4. 图框块（块内含边框和标题栏）→ 扫描 → 应出现；
5. 只有边框多段线、无任何其他图素的图框块 → 扫描 → **不应出现**；
6. 开启"识别四线矩形"后，用 4 条直线拼一个空框 → 扫描 → **不应出现**；拼一个内部有图素的框 → 应出现；
7. 相邻排布的多个真实图框 → 扫描 → 全部出现、顺序正确；
8. 旋转 UCS / 图纸空间布局下重复 1、3 两项 → 行为一致。

## 七、遗留事项

- 本修复使空框过滤**首次真正生效**，部分用户图纸中原本会被扫出的空矩形将不再进入打印清单——这是文档一贯承诺的行为，但建议在发布说明中提示用户；
- 若未来需要"几何级穿越检测"（把大实体包盒恰好压住候选导致的保守保留也滤掉），可在现有 `ContentBox` 基础上对相交盒追加精确几何判定，或在"当前视图内候选"场景引入 `SelectCrossingPolygon` 复核；当前版本从保守性出发不予采用。
