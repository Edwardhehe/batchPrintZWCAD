# LA批量打印 项目全面审查报告

- 审查日期：2026-09-13
- 审查对象：`wangshun` 分支 @ `ab19007`（v1.15.7.1），工作区干净
- 审查范围：全部 102 个 `.cs` + 16 个 `.xaml`（约 3.8 万行），4 个项目，外加构建脚本、资源、文档与仓库卫生
- 审查方法：按层四路并行深审（服务层 / 命令与基础设施层 / 视图层 / 平台适配与构建），关键结论逐条人工复核源码确认；未能复核的均标注"疑似"

## 一、总体结论

工程纪律明显高于一般 CAD 插件的平均水平：事务与对象生命周期管理严格，JSON 存储有原子写 + 备份 + 版本迁移，版本号在 9 处全链路一致，`ARCHITECTURE.md` 等 文档质量高。资源泄漏类问题基本没有发现。

但存在 **2 个已确认的功能级缺陷、1 个用户可见乱码、若干跨层复制与双平台"单边修复"漂移**。最大的工程短板是 **没有测试工程、没有 CI**——这个项目的几何计算密度很高，又要在 3 个平台上跑，恰恰是最需要回归测试的形态。

| 维度 | 评价 |
| --- | --- |
| 架构分层 | 良好。Common 共享 + 双平台薄适配层，单 DLL NETLOAD 方案成熟 |
| 资源管理（事务/Dispose） | 优秀。未发现确认的 Transaction/DBObject 泄漏 |
| 文件写入安全 | 良好。多数路径 temp→验证→替换；少数路径仍直写（PMP） |
| UI 层 | 中。WPF 迁移执行到位，但 code-behind 膨胀（最大 2636 行）且两主窗范式分裂 |
| 双平台一致性 | 中。约 70% 行数对称，确认 4 处"一边修了另一边没修" |
| 异常兜底 | 弱。无全局异常钩子，主窗部分入口无 try/catch |
| 可测试性 | 弱。无任何测试工程与 CI |

## 二、已确认的关键问题（人工复核过源码）

### K1（严重）通用型批打的"空框过滤"实际恒真，过滤完全失效

- 位置：`src/Common/Services/Scanning/RectangleFrameScanner.cs:1982-2125`
- `FilterEmptyRectangles` 预扫描把布局内**所有**实体的外包盒收进列表（含候选矩形自己的边框多段线/线段），随后 `AnyIntersects` 对每个候选做相交判断——候选框必然与自身边框实体相交，判断恒真，过滤是空操作。
- 注释（`:1989-1993`）明确声称"非矩形框自身的实体"，`docs/ARCHITECTURE.md` §5.3 也写着"矩形框多段线自身不计为内容"——**实现与注释、文档三处不一致，实现是错的**。
- 后果：任何恰好符合纸张比例的空矩形（临时标注框、图例框）都会进入打印清单，打出空白页。
- 修复方向：预扫描时记录并排除"包围盒与某候选重合"的实体，或把候选边框实体的 ObjectId 集合传入收集器排除。

### K2（严重）打印期间窗口未禁用 + 消息泵，用户操作可重入破坏打印状态

- 位置：`src/Common/Views/BatchPlotForm.xaml.cs:1961-2045`、`RectangleBatchPlotForm.xaml.cs:1323-1374`
- `ExecutePendingPrint` 在 UI 线程同步跑打印循环，靠 `PumpMessages()`（Dispatcher 空任务的 DoEvents 等价物）刷新进度，但**没有 `IsEnabled = false`**（对比同文件 `SplitSelectedDwgs:1481` 拆图时是禁用的），只有打印按钮自己变成"停止"。
- 打印中每张图之间消息泵会处理用户点击 → "扫描当前图"（`:189`，无 `_printCts` 守卫）、"多文件批打"、"图号重排"均可重入 → `SortAndRefreshOutputPaths` 会重排 `_jobs` 并改写共享 `PlotJob.OutputPath`，与打印循环保存的 `originalOutputPaths` 及合并 PDF 的临时路径互相踩踏；文档锁在打印与重入扫描之间交替获取，有锁冲突风险。
- 修复方向：打印期间整体 `IsEnabled = false`（保留停止按钮），或在各入口加 `_printCts != null` 守卫。

### K3（中，用户可见）进度窗显示乱码 `"??????u"`，源文件编码已损坏

- `src/Common/Infrastructure/RectangleScanProgressSession.cs:44`：`window.ReportScan(0, 0, "??????u")` 经字节级验证就是 6 个问号 + u 的字面量，扫描开始时直接显示给用户；该文件与 `src/Common/Commands/RectangleBatchVerifyCommands.cs` 的中文注释已不可逆丢失（曾是 GBK 被按错误编码保存）。
- 另外 `RectangleScanProfileCommands.cs`、`RectangleScanProgressSession.cs` 含 GBK 高位字节且无 BOM，跨机器/跨区域编译有再次乱码风险。建议统一转 UTF-8（带 BOM）并修复该字符串。

### K4（中-高）无全局异常兜底，部分扫描入口裸奔，异常直达 CAD 宿主

- 全仓库没有任何 `DispatcherUnhandledException` / `AppDomain.UnhandledException` 注册（grep 确认）。
- `BatchPlotForm.xaml.cs:189-218` `ScanCurrentDrawing` 对 `TitleBlockScanner.Scan` 无 try/catch（对照 `RectangleBatchPlotForm.xaml.cs:678-708` 同名方法有完整保护）；非模态面板按钮处于应用上下文，异常无人接管时在 AutoCAD/ZWCAD 中通常表现为宿主崩溃。
- 建议：Initialize 时挂全局异常钩子写日志 + 温和提示；主窗扫描入口补齐与通用型窗一致的异常包装。

### K5（中）K1 连带：文档与实现一起错

`docs/ARCHITECTURE.md` §5.3 对空框过滤的描述与错误实现一致，修复 K1 时需同步修订，否则文档会"证实"错误行为。

## 三、分层问题清单

### 3.1 服务层（Scanning / Plotting / Paper）

**重要：**

1. **PMP 自定义纸张写入非原子**：`src/Common/Services/Paper/PmpCustomPaper.cs:195,279,353,557,633` 直接 `File.WriteAllText`，批量路径 `:457` 用 `File.Copy(..., true)` 截断覆盖；单张打印主路径 `SinglePlotCommands.cs:140` 直调真实 PMP，中途崩溃/占用会把 `LA_pdf.pmp` 写坏。同仓库 `DwgSplitService.ExecuteWithSafeOutput`（`:359-405`）已有 temp→验证→`File.Replace` 的正确范式，应统一。
2. **静态可变缓存无锁保护（疑似）**：`RectangleFrameScanner.cs:41,45,210-217`、`CadTextExtractor.cs:1256-1280` 的缓存与 `[ThreadStatic]` 上下文依赖"全在 UI 线程同步调用"的调用约定；`BlockDefinitionCache` 只在入口 Clear、异常路径不清。打印一旦后台化即成竞态隐患。
3. **批量反写图号失败语义与单张不一致**：`CadTextUpdater.cs:78-109` 整组共用一个事务，单 job 失败后继续并统一 `Commit`，已写部分持久化；单张路径 `:135-147` 失败即整体回滚。同一次"图号重排"两种路径结果不同。
4. **反写范围小于扫描范围（疑似）**：扫描能收集与字段区域重叠的其它块内文字（`CadTextExtractor.cs:777-899`），反写 `CadTextUpdater.UpdateRegionText`（`:311-367`）只处理自身块属性与 owner 顶层文字——"识别到了但反写报未找到可写文字"的功能性不对称。
5. **几何/坐标函数跨文件逐行复制**：`HasMeaningfulOverlap`/`TransformExtents`/`OffsetRegion` 等在 `TitleBlockScanner.cs:681-870` 与 `CadTextUpdater.cs:379-533` 几乎逐行重复；`IsBlockClipped` 两处、`IsEntityVisible` 三处、`UnlockLayers` 两处。比例/容差语义一旦调整极易只改一处。

**轻微（摘要）：**

- `CadEntGet.cs:128-133` 解析失败整个会话永久禁用且无日志；`:23-28` 仅支持 x64。
- `TianzhengTextReader.cs:112-115` 无包围盒时退化为 (0,0)，可能落进字段区误匹配。
- `CadTextUpdater.cs:567-576` `Path.GetFullPath` 可破坏 Try 前缀不抛异常的约定。
- `DwgDatabaseCleanup.cs:49-64` `TryActivateLayout` 死代码，`DwgPaperSplitter.cs:129` 注释与行为不符。
- `DwgSplitService.cs:32-35` 注释称"借用内存数据库含未保存修改"，实际内容来自磁盘文件。
- `PdfDocumentService.cs:126-131` 删除→移动窗口期丢旧文件；`:317-332` 损坏 PDF 空转 6 秒且原始异常被抹平。
- 两套点在多边形内判定实现不一致（`RectangleFrameScanner.cs:947` 的 1e-30 偏置 vs `DwgSplitGeometry.cs:1044` 无偏置）。

- `ScaleSettingsPicker.cs:53-56` 框选短边按 WCS 直接取 X/Y 差值，旋转 UCS 下推荐比例错误（疑似；项目已有 `CadCoordinateSystem` 处理方案未复用）。

- `PaperSizeDetector.cs:793-819` 每候选 ~(34+自定义)×5×2 次评估 + `FilterRectangles` O(n²)，大图扫描瓶颈。

**重要：**

1. **WCS→DCS 的 ViewTwist 符号疑似与惯用公式相反**：`src/Common/Commands/CoordinateUtils.cs:53` 用 `Rotation(-view.ViewTwist, ...)`，与社区成熟实现（Kean Walmsley / DevBlog）仅差一个负号；同一公式又复制在 `TemporarySequenceOverlay.cs:80`。若确属错误，ViewTwist≠0 时所有打印窗口会转错。**需设 VIEWTWIST 实测后定论，并抽成公共函数。**

5. **非模态批打窗持有创建时 Document，文档关闭后悬空（疑似）**：`BatchPlotCommands.cs:331,360` + `BatchPlotForm.xaml.cs:40`、`RectangleBatchPlotForm.xaml.cs:123`；无 `DocumentManager.DocumentDestroyed` 订阅。设置窗有等价防护，批打主窗没有。

## 四、横切面问题

1. **无测试、无 CI**：无任何测试工程，无 `.github` 工作流。几何计算密度高 + 三平台矩阵，正是最需要回归测试的项目形态。建议先从纯计算类（`PaperSizeDetector`、`SpatialSorter`、`FileNameSanitizer`、`NaturalStringComparer`、`DwgSplitGeometry` 的纯函数）入手建最小测试工程，并加 `dotnet build` CI。
2. **复制粘贴式重用是最大维护隐患**：几何/坐标换算（服务层 5 组）、两主窗体 UI 逻辑（6 组）、ZWCAD/AutoCAD 平台层（约 70% 逐行复制）三个层面都靠"复制后手改"。已确认 4 处平台漂移、2 处窗体行为漂移——这正是复制路线的必然结果。建议分阶段抽取：先纯函数（几何/坐标），再 UI 助手类。
3. **源码编码卫生**：统一 UTF-8 BOM，修复已损坏文件。
4. **文档质量总体优秀**（`ARCHITECTURE.md` 1173 行结构清晰、wpf-migration-spec 精细），但 K1/`TryActivateLayout`/`SourceDatabaseContext` 等 3 处注释与实现不符，说明"文档跟代码一起漂"的风险已经出现。

## 五、做得出色的方面

1. **事务与对象生命周期纪律**：全库 `using` 事务 + 失败不 Commit 即回滚；层锁先记录后恢复；`WorkingDatabase` 保存/恢复；临时标识三条路径（保存/取消/异常）都清理。未发现确认的 Transaction/DBObject 泄漏。
2. **JSON 存储健壮性**：temp + `File.Replace` 原子写、自动 .bak、损坏区分 Newtonsoft 失败与文件损坏、`DirectorySettingsVersion` 渐进迁移。
3. **PGP 管理防御性**：字节级备份永不覆盖、BOM/UTF-16 探测原样回写、旧块字节级清除、别名合法性校验与冲突检测——"改用户系统文件"这种高危操作做到了库内最高水准。
4. **CAD 集成落点正确**：模态/非模态统一走 `CadApp.ShowModalWindow/ShowModelessWindow`；预览经 `PendingPlotPreview` + `SendStringToExecute` 保证 PlotEngine 在命令上下文启动（明确解决了"假启动"）；`CadWindowFocus` 的 Hide/Restore 全部 try/finally 配对。
5. **文件写入原子范式**多数路径落地：拆图 temp→验证→`File.Replace`、PDF 合并、转图 staging、批量 PMP staged 副本，失败均清理半成品。
6. **发布工程完整**：版本号 9 处一致、打包带 SHA256 manifest 与防重、AutoCAD 绘图仪安装"失败封闭"（临时文件 + 备份 + 写后校验 + 路径白名单，绝不触碰用户自有 PC3）。
7. **性能工程有据**：空框过滤 O(R×E)→O(E+R×B) 的动机、四叉树邻域搜索、重建键比对避免无谓重画、`RaiseListChangedEvents=false` 消除 O(n²) 重绑。
